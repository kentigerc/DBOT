## Verified issues fixed

1. **Browser-accessible trading OTPs bypassed the protected bridge.** The unused `POST /api/connection` endpoint returned a Deriv one-time WebSocket credential after account/terms checks. An authenticated caller could connect directly to Deriv, avoiding the bridge's purchase serialization, journal, and message controls. Removed the HTTP route; it returns the generic API 404. Server tools and the WebSocket bridge retain internal OTP issuance. No frontend runtime callers were found. Tests now exercise OTP authorization internally and separately prove that guest/authenticated HTTP requests cannot retrieve it or trigger upstream OTP issuance. External clients depending on this undocumented endpoint must use `/api/socket`.
2. **Authorization could outlive logout during asynchronous work.** Account ownership, owner authorization, and demo-account selection verified revocation before account discovery but did not recheck after it. OTP issuance likewise did not recheck after its provider response. Added post-wait verification; tests simulate logout saved by another handler instance while each operation is suspended. Builder purchases now also recheck session validity after acquiring their journal/lock permit and before forwarding a buy. A failed check cancels the unsent permit. The regression demonstrates that the pre-fix bridge forwarded the buy after logout; the patched bridge refuses it without an upstream send. This closes the tested windows; it cannot recall a request already sent to Deriv or make the local revocation check and a remote purchase one atomic transaction.
3. **Hosted bot downloads ignored shared logout revocations.** The loader only checked encrypted-cookie expiry. A captured, unexpired cookie still downloaded protected XML after logout. It now awaits the shared session verifier. A real encrypted-session regression first loads a bot successfully, marks the session revoked in shared storage, and verifies the identical cookie receives 401 with no XML.

Each new regression was run against the relevant pre-fix behavior and failed as expected before its fix. Existing OTP ownership, destination pinning, terms, expiry, provider cooldown, and no-retry tests were retained and moved to the internal issuer where needed.
